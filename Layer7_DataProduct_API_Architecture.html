Key Design Principles
Storage Agnosticism
Consumers access the same APIs regardless of whether data originates from Kafka/PostgreSQL, S3, SingleStore, or IOMete. The storage technology is invisible to the consumer.
Consumer Decoupling
Applications and AI agents do not need to know SingleStore from IOMete. Migrations, upgrades, or storage changes become invisible to consumers.
Agentic AI Ready
Agent-friendly API design — structured, predictable, schema-documented responses. GraphQL for flexible queries. Knowledge Graph integration via Graph API.
Governed at the Border
All access flows through the gateway — authentication, authorisation, rate limiting, and audit logging are enforced uniformly regardless of who is calling.
Open Standards
REST, GraphQL, OpenAPI — no proprietary protocols. Integrates with any consumer tool, language, or framework.

🛠️ Recommended API Gateway Options Evaluated against your Azure / IOMete / Kubernetes stack
Azure APIM
Tightest Azure AD integration · Managed service with built-in Developer Portal · Policy engine for rate limiting, transformation · Native Entra ID RBAC · Best fit for Azure-first estates with IOMete on AKS
Google Apigee
Enterprise-grade · Advanced analytics and monetisation · Multi-cloud deployment · Best-in-class developer experience · Strong for organisations with GCP footprint alongside Azure
Kong Gateway
Open-source core · Kubernetes-native — aligns with IOMete's K8s deployment model · Rich plugin ecosystem · Cloud-agnostic · Ideal if avoiding vendor lock-in at the gateway layer too
AWS API Gateway
Serverless · Native AWS IAM and Cognito integration · WebSocket and REST/GraphQL support · Best for AWS-hosted Data Products and Lambda-backed APIs
Recommendation: Given your Azure AD / IOMete / Kubernetes stack — Azure APIM provides the tightest identity and governance integration. Kong is the best alternative if you want Kubernetes-native deployment that mirrors IOMete's architecture philosophy. Either can coexist.
